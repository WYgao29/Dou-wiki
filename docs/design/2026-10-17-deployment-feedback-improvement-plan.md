# 抖库部署反馈改进方案

状态：用户已于 2026-10-17 批准三批修改；实施中，每批验证后进行 review，修复后再次 review。

日期：2026-10-17。基准：`36697c3`，包版本 `0.2.1`。

本方案根据 Claude 的部署反馈及逐项代码核查编写。目标是减少采集失败、保留已有识别成果、让证据精度清晰可见，并改善资料阅读和接入体验。建议分三批实施，每批单独验收；也可以只批准第一批。

## 1. 审核摘要

| 批次 | 用户得到的结果 | 主要内容 |
| --- | --- | --- |
| 第一批：运行可靠性 | 能下载、能排障，补导按指定策略处理 | 媒体发现、结构化错误、保留参数、离线模型、浏览器体检、日期格式和安装说明 |
| 第二批：识别与证据 | 对齐异常时保住全文，引用不夸大精度 | 分阶段保存、有限降级、时间精度传递、歌词使用规则、OCR 连续引用 |
| 第三批：材料与搜索 | 看得到关键帧，能按含义查资料 | 关键帧清单与画廊、分开保留素材、网页语义搜索、简明接入路径 |

建议批准三批范围，按顺序完成。以下两项涉及默认行为，请重点审核：

| 决策 | 推荐选择 | 兼容处理 |
| --- | --- | --- |
| 对齐失败后是否继续 | 完整识别已成功、仅指定对齐错误时，保留全文并以“时间粗略”的提示继续 | 提供 `fail / retain_window` 配置；新安装推荐后者，已有配置缺字段仍按 `fail`；升级现有安装时按本次批准的选择显式配置 |
| 关键帧保存多久 | 新采集默认视频/音频临时保留 30 天，关键帧长期保留 | `retention=keep` 仍保留全部，`discard` 仍清理全部；已有条目维持原策略，不自动延长保留时间 |

审核本方案只启动已批准范围的开发与验证。本次交付不修改运行代码，也不切换本机服务。

## 2. 沿用的项目约定

- 作品校正与分析继续由当前 Gateway Agent 完成，Worker 负责本地识别、材料整理和发布。
- MCP 工具名称、已有参数及默认协议保留；必要的新参数均为可选。既有 Web 路径、状态码、静态资源 URL 和 CLI 别名保留。
- 继续使用 Python、FastAPI、Jinja2 和原生 JS/CSS；本轮不增加对话模型、音频分类模型或前端框架。
- 保留 schema 16，本方案使用现有任务/资料 JSON 和兼容的侧车字段扩展，不建立另一套数据库迁移流程。侧车是随资料保存、供程序恢复数据的文件。
- 原话、校正、OCR、推断和灵感继续分别保存。新增质量信息不能只存在任务回执里，资料保存、重启和索引重建后也必须可恢复。
- 源码开发、安装包验收与现用 runtime 分开；不在现用环境执行依赖同步，不直接改用户 Vault、状态库或登录 Profile。
- 已有[画面检索方案](visual-search-indexed-plan.md)及其独立分支保持原范围。本次“网页语义搜索”查找文字含义；“关键帧画廊”展示已有图片，两者都不接入新的多模态模型。

## 3. 第一批：运行可靠性

### A1. 媒体发现不再只依赖旧 CDN 域名

根据成功的媒体响应、作品接口提供的播放地址及媒体标识收集候选，兼容 `zjcdn.com` 等域名。目标作品 ID 与播放地址的关联仍是最终选择条件，不能因为某个响应是 `video/*` 就直接下载。独立音轨也必须属于同一作品。

无匹配结果时，诊断包含候选数量、域名统计、匹配失败原因和是否存在真正的登录提示；不输出完整带签名的播放地址，也不把所有 `Fresh cookies` 错误都当成登录失效。

验收：旧域名、新域名、跳转地址可处理；同时出现广告、推荐视频和独立音轨时仍选中目标；没有可靠关联时返回可解释的失败。

### A2. 分析输入错误返回可修正的信息

在 Service 的分析输入边界转换参数校验异常，再由 MCP 返回稳定的业务错误。新识别出的无效分析输入使用 `invalid_analysis`，包含字段路径、原因、数量或长度限制；已有状态、来源编号及材料版本错误继续使用原错误码。

协议 2 的 6 条 `takeaways` 应明确返回“最多 5 条”，任务仍停留在可重新提交的阶段。真正的程序异常保留故障日志，不能全部包装成参数错误。

协议 1 先保留原有兼容规范化，包括要点截断；发生截断时在回执附带规范化提示，并写明与协议 2 的差异。本轮不把已有合法调用突然改为拒绝。

验收：要点超限、字段类型错误、章节数量超限和无效引用均返回正确字段与原因；失败提交不修改分析成果、不推进任务；修正后可提交成功。

### A3. 补导与同步可显式指定保留策略

为 `import_creator_works` 和 `sync_creator` 增加可选 `retention`。显式选项保存到本批请求，再传给实际创建的子任务；省略参数仍使用当前默认值，保证旧调用兼容。

本轮采用“补齐显式参数”的方案，不猜测多轮导入中哪一次应作为博主永久默认，也不新增博主设置存储。接入示例要求有保留诉求时明确传值。

验收：首次导入、补导、同步均可指定 `keep`；子任务使用已保存的选项，重试不重新解释；处理选项不兼容的活动任务不被错误复用。

### A4. 普通模型加载离线，体检检查实际浏览器

Embedding 普通运行显式只读本地缓存，首次模型准备使用单独的下载步骤。缺少可选模型时继续使用现有字符检索替代，并在体检和网页搜索中说明实际检索能力。复用当前向量兼容检查，避免不同模型的向量混用。

`doctor` 用临时 Profile 启动并关闭实际使用的无界面浏览器，同时检查登录模式所需的浏览器文件。设置有限超时，关闭失败时回收进程和临时文件；不访问抖音，不启动登录流程。

验收：完整模型缓存断网可用；缺缓存时不尝试联网、不长时间重试；缺 headless shell、浏览器无法启动等情况被体检提前识别。

### A5. 统一日期生成并说明 Git 提交失败

概念、实体等新页面复用同一套日期和 YAML 输出方式。时间迁移仅在确有时间内容需要转换时写文件，避免只是更换引号或空行就重写已有页面。

区分“没有变化”“没有 Git 仓库”和“提交失败”。资料已经发布而 Git 提交失败时，保留可读资料并给出提示，不能引导重复采集。并发发布继续使用现有锁；本轮不把未证实的竞争条件当成原因增加新锁。

验收：单线程创建后初始化不出现无意义改动；连续初始化结果一致；模拟提交失败能够定位原因，数据库与资料不因此重复发布。

### A6. 修正安装与运行示例

README 将长期运行示例明确改为 `worker run --forever`，同时解释 `--once` 和当前无参数的一次处理行为；保留现有 CLI 默认值。

HF 示例对每个模式分别写 `--include`。补充模型预下载、Playwright 下载来源和国内镜像安装说明；导出依赖再从镜像安装的流程应保持版本与哈希，并在独立环境验证。简明安装路径使用已经安装的 runtime，不要求用户编写额外 STDIO 客户端。

验收：在独立临时环境按文档完成安装/模型准备检查；文档、命令帮助和正式服务的常驻参数一致。文字修正不增加复述文案的自动测试。

## 4. 第二批：识别与证据

### B1. 保存已完成的识别与 OCR，减少重复工作

将媒体处理拆成可恢复的阶段：音频识别、时间对齐、关键帧提取与 OCR。每个阶段完成后，在有效 Worker 租约内原子保存材料和版本信息；部分写入不能被当成完整结果。

对齐失败不再阻止已下载视频提取关键帧与执行 OCR。当前运行退出或重试时，只复用已经完整保存且与媒体、模型和配置相符的阶段结果。取消和租约丢失仍立即终止后续发布。

验收：识别成功后对齐失败能找到完整识别文本与 OCR；进程中断后可继续，失败窗口不会让成功窗口重复识别；不把部分文本发布为完整逐字稿。

### B2. 仅对明确的对齐错误允许降级

新增 `alignment_failure_policy=fail|retain_window`。只有原始识别完整、文字有效，且现有局部修复已耗尽后，`gross_repair`、`anchor_token_missing` 等经逐项确认的对齐原因才允许进入降级分支；使用明确的允许列表，不捕获全部识别异常。

降级窗口使用真实的原识别窗口起止时间，最多是当前已有的 600 秒窗口。已对齐窗口继续保留精度。不得按字数均分时间，或把一个窗口起点伪装成其中每句话的精确时间。音频损坏、内存不足、识别截断、原文覆盖异常等继续失败，并保留可用于排障的材料。

质量字段采用兼容扩展，至少包括时间精度 `aligned / window / unknown`、实际时间范围和降级原因；旧资料缺字段时按“未记录精度”处理，不重新宣称高精度。

这些信息必须经过原始/校正稿、两种 Gateway 协议、`source_refs` 展开、显式引文校验、资料侧车、检索证据包和网页展示。服务端根据原材料推导引用精度，不能靠 Agent 自行填写；材料或精度变化使旧 `context_revision` 失效。

降级任务成功入库后使用现有“完成并带提示”状态。章节、证据和逐字稿显示“约在 02:00–04:30 范围内，时间未经精确对齐”等可读说明，不显示成精确句子时间。任一输出通道尚不能保留该信息时，禁止开启降级模式。

验收：精确与粗略窗口混合仍保留全文和顺序；两种引用方式都无法去掉精度标记；重建后标记仍在；不允许的故障仍失败；精确样本的既有行为保持。

### B3. 让 OCR 投影与连续引用规则一致

继续禁止跳过有效原文或混合来源。调整去重投影：同一个原始 OCR 记录内，两个已保留行之间如果有被过滤的有效内容，保留这些中间行供连续引用；头尾重复字幕仍可去除，跨帧重复文字继续合并实际位置。

错误详情增加前后引用、断点及修正建议；只有下一个编号实际可用时才返回该编号，不提示客户端填写不存在的引用。空白、标点间隔仍按当前原文恢复规则处理。

更新材料投影版本、Gateway 规则和文档示例；旧上下文提交必须重新读取材料。

验收：原反馈中的隐藏中间行可正常连续引用；真正漏掉原话、跨帧拼接、引用倒序仍被拒绝；去重没有损失独有信息。

### B4. 补充歌词与作者发言的使用规则

明确要求 Gateway 区分配乐歌词、旁白和作者观点；不确定身份时保留原始转写，在分析中说明来源不明，不把可定位文字直接当成作者立场。英文、配乐存在或与文案不同语种都不能单独触发删除。

本轮不引入自动音乐分类模型，不承诺可靠识别所有配乐。以纯口播、纯歌曲、音乐加旁白、外语口播四类样本检查实际分析行为；未完成样本复核的情况保留为能力限制，不能宣称已自动解决歌词分类。

## 5. 第三批：材料与搜索

### C1. 关键帧清单与阅读器画廊

采集时保存帧清单，记录所属作品、相对路径、实际提取时间与材料版本，并随资料侧车保存。资料详情接口按需返回，不增加资料库列表负载。

阅读器在现有材料区增加默认折叠的“关键帧”：缩略图按时间排列，可查看大图，时间可以跳转到尚可用的本地视频位置。没有视频时仍能查看保留下来的帧。

旧条目仅展示可验证属于该作品的现存图片；缺少可靠时间信息就显示“时间未知”，不从序号猜时间。素材已清理时明确显示暂无材料。覆盖普通资料、博主目录、移动端、键盘操作与路径边界。

验收：有/无视频、有/无帧、旧条目、博主路径均正确；只有封面或文件名相似的图片不会混入；刷新不会打断现有阅读位置。

### C2. 视频和关键帧分开保留

新增可选 `keep_keyframes`，只细化 `temporary` 策略；在创建任务时解析并保存有效值。新安装初始化推荐开启，既有配置缺项及旧任务/条目维持原行为。相关采集入口和补导/同步可显式覆盖；有效策略参与处理选项比较，避免不同诉求共用同一份清理行为。

| 保存选项 | 视频和音频 | 关键帧 |
| --- | --- | --- |
| `temporary`，未开启保留帧 | 30 天后维护时移入废纸篓 | 随素材清理 |
| `temporary`，开启保留帧（推荐新默认） | 30 天后维护时移入废纸篓 | 长期保留 |
| `keep` | 长期保留 | 长期保留 |
| `discard` | 按现有完成后清理语义处理 | 同样清理 |

30 天继续使用现有 `retention_days`，以实际配置为准。维护按该条资料保存的策略处理，不用当前全局设置重解释历史条目。保留帧不等于本地视频仍可用，现有视频状态和链接必须正确更新。

预览维护时分别列出待清理的视频和将保留的帧。用户明确删除资料或选择 `discard` 时，关键帧跟随现有素材清理约定处理；已经被清理的帧不自动重新下载。

验收：覆盖表中四种策略、重启、重试、共享采集及索引重建；清理视频后帧仍可读，清理全部后不留下失效画廊链接。

### C3. 网页增加语义搜索

语义搜索是按文字含义寻找相关材料。保留现有关键词搜索及默认行为，增加“语义”选项，复用当前全文和本地向量检索能力；不增加生成模型。

通过新增只读接口提供结果，每条包含资料、命中证据和时间/图片定位。先限制当前博主、标签、内容类型及专题来源范围，再检索和排序，不能先取全库少量结果再过滤。专题无证据时明确返回空结果，不扩大到全库。

没有语义模型时显示能力提示并提供关键词结果；不把字符哈希替代称为完整语义检索。未入索引的只读 Markdown 继续可用关键词搜索，界面说明覆盖范围。

验收：近义表达可命中真实相关证据；原关键词结果保持；筛选范围和专题边界正确；缺模型或本地检索失败时网页仍可使用。

### C4. 接入说明提供一条简明路径

增加“已安装 → 探测 → 注册 STDIO MCP → 获取工具 → 当前会话完成一条任务”的简明示例，详细检查仍指向现有契约，不要求个人用户先建立后台事件桥。

保留全部工具可用，不设置角色白名单；用任务流程图和常用工具表帮助使用。单会话主要使用简短状态轮询；有路由上下文产生的事件仍按现有规则确认。后台接续能力单独说明。

工具是否占用全部模型上下文应以客户端实际加载记录为准，本轮不以“51 个工具”推导开销，也不增加固定工具数量依赖。
