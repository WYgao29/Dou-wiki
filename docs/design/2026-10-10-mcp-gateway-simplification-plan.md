# MCP 与 gateway 精简方案

状态：方案待审阅，尚未实施。日期：2026-10-10。代码基准：`main` / `6c4fb7b`。

本方案承接用户已经确认的方向：Agent 通过 MCP 使用抖库，作品校正与分析交给 gateway；Web 保留，停止作为创建新抖音导入请求的入口；移除专题生成和 Web 聊天；不需要保留现有业务数据，按空资料库重新开始。gateway 指已连接的 Agent 获取材料，用自己的模型处理，再通过 MCP 提交结果。

旧资料、任务、专题、生成成果和聊天记录不进入新库，不设计旧数据迁移、历史读取或旧任务接续。本方案仍保留新库建立之后的持久化、重试、重启恢复及知识索引重建，避免把“不保留现有数据”误解为以后不保存数据。

## 1. 目标与范围

日常流程为：用户把分享文本和灵感发给 Agent → Agent 通过 MCP 创建任务 → Worker 下载、识别和整理材料 → Agent 校正与分析 → Worker 保存资料并建立索引 → 用户在 Web 阅读和管理。

| 部分 | 本次建议 |
| --- | --- |
| Agent 接入 | 只使用 MCP；全部工具可用，按用户任务及已有授权执行 |
| 导入类型 | 保留单条作品、博主、收藏和合集四种；视频和图文均保留 |
| 作品校正与分析 | 只保留 `gateway`，移除 Worker 的 `provider` 和 `local` 执行分支 |
| Web | 保留资料库、阅读、搜索、灵感、专题管理、标签、废纸篓、运行设置和任务管理；移除新导入入口、专题生成和聊天 |
| CLI | 保留安装、配置、授权、服务运行、诊断、维护与知识索引重建命令；停用重复业务操作及旧数据迁移命令 |
| 底层处理 | 保留下载、Qwen3 ASR、OCR、检索、向量、提醒、任务队列、租约和故障恢复 |
| 资料与任务 | 从空 Vault 和状态库开始；新导入继续记录分析、任务、博主及合集关系、收藏清单和共享采集 |
| 专题管理 | 保留新库中的文章分组、来源管理、限定来源检索、笔记保存与查看；移除自动生成成果及其历史读取 |
| 专题生成与 Web 聊天 | 本期移除生成和聊天功能，以及专属模型接口、配置、设置与密钥访问代码；不新增替代生成流程 |

精简后，抖库不再直接调用对话大模型接口，作品校正与分析由外部 Agent 执行；研究和问答也在 Agent 自己的会话中完成。Qwen3 ASR、OCR 和向量模型负责识别与检索，仍由抖库使用，相关模型配置继续保留。

不保留旧业务数据不等于更改仍保留功能的对外接口：现有 MCP 调用参数、Gateway 协议及运行入口按下文处理，外部 Agent 的配置和抖音登录 Profile 不属于本次业务数据清理范围。

## 2. 最新代码对方案的影响

当前源码和本聊天加载的 MCP 均提供 52 个工具，其中 8 个属于新加入的合集功能。本方案移除 `generate_topic_artifact` 的工具注册；按当前集合计算，保留 51 个工具。实际清单以实施后的 `tools/list` 为准，不写入固定白名单。

合集及最近的共享采集修复已经进入主线。同一作品从不同导入方式进入时可以共用一次下载和分析，每个调用仍保留自己的任务记录、灵感及会话信息；取消、失败重试、重启恢复和结果回投均依赖这些关联。这些能力继续服务新库，因此保留 `batch_capture.py`、`capture_sharing.py` 及相关事务、租约和回归用例。

最新代码有一项需要先修复的兼容问题：`allow_long` 和 `approve_cloud_analysis` 已不再控制处理授权，但部分共享判断仍比较整个 `CaptureOptions`。仅这两个旧字段不同，就可能使同一作品不能复用活动采集。博主和合集的派发也存在这种比较；收藏需要接入同一规则，避免忽略仍然有效的选项差异。

当前 CLI `configure-model` 会同时把 `analysis_mode` 改为 `provider`。本方案停用该命令，删除 Web 共用模型设置及切换到旧模式的逻辑；安装和诊断不再要求配置对话模型或访问其密钥。

## 3. Web：停用创建入口，保留既有任务管理

本方案以“是否创建新的导入请求”区分导入入口和任务管理。Web 不再接受新的分享文本、博主、收藏或合集扫描请求；在新库中由 MCP 创建的批次仍可查看清单、选择、确认、取消及失败重试。这些操作使用原任务及其 Gateway 信息。

移除侧栏和命令面板中的新导入按钮、`Cmd+I` 导入快捷键、分享文本粘贴自动打开导入的行为，以及空资料库等页面里的导入引导。保留新库的“导入内容”记录列表和任务中心，不因名称包含“导入”而删除整个页面。

Web 后端也停止创建新请求，不能只隐藏按钮。下列入口保留路径并统一返回 `410 Gone`，给出改用 Agent 的说明；停用后不创建任何任务：

| 当前入口 | 当前行为 |
| --- | --- |
| `POST /api/captures` | 创建单条采集任务 |
| `POST /api/creators/inventory` | 创建博主清点任务 |
| `POST /api/favorites/imports` | 创建收藏清点任务 |
| `POST /api/collections/inventory` | 创建合集清点任务 |
| `POST /api/creators/{creator_id}/sync` | 创建新一轮博主导入任务 |
| `POST /api/creators/{creator_id}/import-skipped` | 创建此前跳过作品的导入任务 |

新库任务的 GET、选择、确认、取消和重试接口保留，不恢复被舍弃的旧任务。仍有效的任务 URL 展示新库任务；已不存在的旧任务 ID 按正常不存在处理；旧新建链接显示简短说明，不打开提交表单。

Web 仍展示共享采集的实际执行者、阶段、进度及授权状态，并保留跳转入口。既有资料的重新分析功能也保留，执行方式统一为 gateway；等待 Agent 的任务必须显示明确状态和 `job_id`，可由 Agent 通过 MCP 接续，不宣称 Web 能主动唤醒已结束的 Agent 对话。

`webapp/static/imports-*.js` 当前同时承担新建和既有任务交互，只删除已核实属于新建入口的代码。保留仍被阅读页、任务页及历史链接使用的资源 URL、加载顺序和公共模块。

移除专题的六类自动成果生成按钮及其专属展示代码，保留专题笔记展示；移除 Web 聊天标签、消息输入、会话操作和 AI 对话快捷键。右侧面板仍承担文章信息、灵感和专题来源管理，不能因部分元素 ID 含 `chat` 就删除整个面板。模型设置入口和连接测试也移除；旧链接显示功能已停用，其他运行设置继续使用。

## 4. 作品处理与兼容

### 4.1 统一 gateway

`service.py`、`service_capture.py` 和 `service_analysis.py` 统一由 gateway 执行作品校正与分析。视频采用现有的“等待校正 → 提交校正 → 等待分析 → 提交分析 → 发布”流程；图文按现有流程直接等待分析，不新增语音校正阶段。重新分析和失败恢复根据已有材料进入对应阶段，复用阶段与结果校验。

移除 `provider` 的直接模型校正、分段汇总和标签归纳，以及 `local` 的启发式分析。删除专属实现前检查引用，保留或迁移仍被 Gateway 结果校验、专题笔记或新库恢复使用的公共类型，再删除 `adapters/llm.py` 中失去调用方的实现。保留功能的 Service 公开方法继续兼容，停用功能的处理见第 5 节。

新部署使用不含对话模型设置的新配置，作品处理只支持 `gateway`。不实现旧 `provider` / `local` 配置和检查点的迁移；停用模式及未知模式明确报错，不继续调用旧实现。`configure-analysis-mode` 保留命令入口，但不再允许写入已停用模式；`configure-model` 仅保留停用提示，不询问或保存密钥，不连接模型，也不重启服务。

旧资料不导入新库，旧任务不接续，不保留读取旧库历史分析和接续旧任务的分支；仍保留功能的接口格式按第 4.3 节处理。新库中的 Gateway 任务仍保存下载、原稿、校正稿和分析检查点；失败重试与服务重启复用这些材料，不能因采用空库起点而删掉正常恢复能力。保留当前资料存储和索引的主要结构，不借本次精简重做整套存储。

### 4.2 有效选项与共享采集

已有 MCP 接口中的旧授权参数继续接受，兼容仍使用这些参数的客户端；不为旧任务记录提供数据迁移。它们不再触发授权提醒，也不参加共享兼容性比较。集中定义“影响实际处理的选项”，当前 `CaptureOptions` 中只包含 `retention`，即媒体保留策略。

短链解析后的共享、博主派发、收藏派发和合集派发使用同一比较规则。仅旧授权字段不同允许共享；媒体保留策略不同仍明确报告冲突。批量派发先检查全部候选，再发布子任务，不能在发现冲突前留下部分已派发的批次。

保留调用者自身 `job_id`、Gateway 上下文、灵感和事件路径，以及 `shared_capture_job_id` / `shared_job_status`。等待者单独重试时清除旧执行者关联；普通任务重试继续保留有效检查点。取消某个批次不影响其他仍需要同一作品的调用者。

### 4.3 MCP 与持续执行

除已决定停用的 `generate_topic_artifact` 外，保留已有 MCP 工具名称、参数和 Gateway 协议 1 / 2；两种协议属于传输格式，不是要删除的分析模式。Agent 优先使用协议 2，旧客户端仍可使用协议 1。专题创建、来源管理、限定来源检索和笔记保存工具继续使用。

任务创建回传的 `job_id` 是中间回执。Agent 在当前任务中继续查询状态、获取对应阶段材料并提交结果，直到完成、失败或确实需要用户输入。共享等待者按执行者 ID 获取分析材料，完成反馈仍返回原调用会话。

MCP 本身不负责唤醒已结束的对话。客户端支持后台接续时可以使用现有事件与确认机制；没有这种能力时，应在当前任务中继续等待和执行。接入说明不要求连接另一套知识库，不要求长视频确认，也不强制安装额外心跳服务。

抖库源码继续由 Codex 维护。其他 Agent 可使用全部 MCP 工具完成获授权的任务，对源码仓库只读，配置、技能、脚本、日志和临时文件存放在仓库外。本方案不修改 Hermes 或其他客户端的文件。

## 5. CLI、专题生成与 Web 聊天的处理

CLI 保留 `init`、授权、`doctor`、Worker、Web、服务安装卸载、维护和新库知识索引重建等运行命令。LaunchAgent 当前依赖 `worker run --forever` 与 `maintenance run --apply`，其 console scripts 和调用方式保持有效。`configure-model` 与业务命令一样停用；旧词汇、校验字段和封面等一次性数据迁移命令不再保留执行实现。

采集、批量导入、查询、业务任务操作、资料分析、专题及灵感等命令不再执行重复业务实现。旧命令名与别名保留统一停用提示，并以非零退出码说明对应 MCP 用法；没有替代工具的专题生成、模型配置及旧数据迁移命令直接说明功能已停用。已有隐藏的 `gateway monitor-events` 先保留为旧事件桥接兼容入口，不作为新 Agent 接入方式；确认实际引用后再单独决定是否删除。

### 5.1 停用生成与聊天

| 功能 | 实施方式 |
| --- | --- |
| MCP 专题生成 | 从工具清单移除 `generate_topic_artifact`，同步删除 Agent 指南中的调用要求；其他专题工具保留 |
| Web 专题生成 | 移除生成按钮；`POST /api/topics/{topic_id}/artifacts` 返回 `410 Gone`，不生成或保存成果 |
| Web 聊天 | 移除聊天界面、执行代码、专用数据模型和表；旧会话及消息接口返回 `410 Gone`，不写数据或调用模型 |
| 模型配置与测试 | 移除共用模型设置；`/api/settings/model`、`/api/settings/model/test` 和 `/api/system/model-health` 返回 `410 Gone`，不连接模型或访问密钥 |
| 旧 Service 调用 | `generate_topic_artifact` 的公开方法暂保留相同参数并明确报功能已停用，不保留生成实现 |

不新增 Agent 专题生成、成果提交或后台唤醒接口，也不将其列为下一期。外部 Agent 可以使用保留的检索和读取工具完成研究、问答；用户要求保存时，仍可使用现有 `save_topic_note` 保存笔记，不将其标记为原六类自动生成成果。

移除 `adapters/chat.py`、`webapp/chat.py` 中的聊天执行与上下文构造，删除其在 Web 初始化、Service、设置和诊断中的引用。运行时移除 `LLMSettings` 及相关调用配置，新生成配置不含 `[llm]`，不设计旧模型配置迁移。删除仅供这些功能使用的密钥访问代码。`httpx` 仍用于分享解析和媒体下载，保留该依赖；其他依赖只有确认失去全部引用后才删除。

### 5.2 空库起点与数据结构

新库不接收旧 Vault、SQLite 状态库、任务、专题、自动生成成果和聊天记录，不导出旧数据再导回，也不把旧库可读作为验收条件。部署使用新版生成的配置和空库，不做在途旧任务的排空或恢复。

删除自动成果的生成、显示和旧格式读取，删除聊天专用表、持久化方法、旧 schema 迁移及资料删除恢复中的聊天关联分支。专题仍需要保存来源和笔记，只保留这些新功能需要的数据结构、引用版本和索引重建逻辑；不为了兼容旧自动成果而保留整套实现。

资料删除、废纸篓恢复、媒体保留、来源更新和知识索引重建继续作用于新库。新产生的资料及任务正常保存，不影响以后服务升级所需的有效数据结构。

Web 停用接口改为 `410`、业务 CLI 改为停用提示、MCP 移除专题生成工具，都是本次精简有意改变的行为。实施时在更新日志和接入文档列出，客户端重新连接以更新工具清单；不能把“名称仍在”写成“行为完全兼容”。保留范围内的接口、状态码和负载继续兼容。

删除项目内的模型调用代码和配置入口，不修改外部 Agent 的模型设置，不停用本机独立模型服务，也不清除已有 Keychain 密钥或下载的模型。

## 6. 实施顺序与验收

| 顺序 | 修改范围 | 验收条件 |
| --- | --- | --- |
| 0. 固定旧版基准 | 记录精简代码修改前的完整 Git 提交，并保留版本标记 | 后续可按同一提交取得旧版源码、依赖锁文件和构建配置；本轮文档改动不等于已固定归档版本 |
| 1. 共享选项修复 | `models.py`、`batch_capture.py`、`capture_sharing.py`、`collection_store.py`、`favorites_store.py`、`database.py` | 旧授权字段不同仍复用一次采集；有效选项不同明确拒绝且不留下半个批次；取消、重试、会话反馈保持正确 |
| 2. 执行、数据结构与模型依赖精简 | Service、`database.py`、`models.py`、`config.py`、`setup.py`、`web_operation.py`、专属分析与聊天适配器 | 空库可初始化；作品只由 gateway 校正分析；移除专题生成、聊天执行、专用表和旧数据迁移；新任务恢复及专题笔记正常 |
| 3. 入口与文档精简 | `cli.py`、`mcp_server.py`、Web 路由、模板、JS、README、架构及 Agent 指南 | 无 Web 新建、专题生成、聊天和共用模型入口；既有任务、阅读、搜索、专题管理和运行命令继续工作；MCP 清单不含专题生成工具 |
| 4. 发布检查 | 正式回归、浏览器验证、包检查和实际服务探针 | 不连接对话模型、不要求其密钥；识别和检索正常；保留接口及资源可用；实际 MCP 与 Worker/Web 使用本次版本 |
| 5. 旧版归档 | 精简版本开发完成后，从固定的旧版提交制作源码包、wheel 和版本说明 | 包与提交对应，文件校验通过；归档放在源码仓库外，不作为本机运行版本 |

专题生成与 Web 聊天的删除纳入本次实施范围，没有保留其模型调用的后续阶段。每个批次完成后检查差异并分别提交，出现问题可定位和回退。运行验证从空库开始，不实施旧业务数据迁移。

验证复用正式回归和现有 Gateway 辅助函数，调整 `tests/conftest.py` 中依赖假 provider 的通用夹具，解除 `tests/support/web.py` 及浏览器验证入口对假聊天 provider 的依赖。删除已停用功能的专属成功路径和旧业务数据兼容用例，改为检查停用入口无副作用；保留发布、索引、共享、取消、租约、新任务恢复和专题管理用例。`tests/test_topics.py`、`tests/test_web.py`、`tests/test_collection_interfaces.py` 等混合功能文件按行为调整，不整文件删除。

重点场景包括：空库初始化；单条短链与批次重复；不同 Agent 共用作品；四种入口的有效选项比较；批次原子派发；共享等待者重试；Worker 重启和租约失效；协议 1 / 2；Web 停用接口无副作用；新批次选择、确认和重试；专题创建、来源管理、笔记及重建；资料删除恢复不依赖聊天表；右侧信息、灵感和来源面板；无对话模型或密钥时 Web、Worker 和诊断正常。

完成相应变更后执行 `uv run --no-sync ruff check src tests` 和 `uv run --no-sync pytest -q -m 'not live'`，不在现用 `.venv` 同步依赖。浏览器检查覆盖桌面与窄屏、命令面板、旧链接和共享任务跳转。发行包验证使用独立运行环境；真实网络及账号检查单独选择，不作为 Agent 日常接入前置步骤。
