**Tech Stack:** Python 3.12、MLX、`mlx-audio==0.5.8` 基础包（先验证最小依赖）、SoundFile、Hugging Face 本地快照、pytest、现有 Service / Worker / Web / Gateway。

## Global Constraints

- 平台 Apple Silicon Mac Studio，64 GB 内存，Python 3.12；保留项目 `>=3.12,<3.14` 约束及现有非 ASR 功能。
- 最终只有 Qwen3；**任务 6 的删除前验收通过之前，禁止删除旧实现和旧引擎专用测试**。
- `TranscriptSegment`、`transcribe(audio_path, output_dir)`、artifacts 键、CLI/MCP 和 Web 路径保持兼容；provenance 只增加字段，旧记录不改写。
- 输入 16 kHz 单声道；最大时长 120 分钟；默认段上限 30 秒，允许配置范围 5–60 秒；静音/零采样返回空列表。
- 默认 bf16 模型及 SHA、Silero SHA、ITN 规则和错误分类采用规格中的精确值；ASR 不联网、不运行远端模型代码。
- 冷加载 ≤10 秒；包含读取/VAD/ASR/ITN 的 RTF ≤0.1，冷调用也记录含加载的总时间；10 分钟端到端处理 ≤60 秒；内存必须实测，不把此前估计当成验收结论。
- 在仓库外独立环境安装和测试；现用仓库 `.venv`、真实 Vault、状态库、浏览器 Profile、oMLX 服务均不因计划或实验被改写。
- 真实测试只读既有素材并写测试 Vault；新素材下载、生产环境升级和旧缓存卸载不属于本计划的自动执行步骤。
- 用户已确认本次不做旧数据重转，先完成 Qwen3 替换；以后新增重转先补独立方案与计划。
- 本期不做热词、上下文提示和术语仓库；Qwen 生成参数为 `system_prompt=None`、`hotwords=None`，不新增提示配置、接口、记录或对比验收任务。

## Review Focus

以下条件已分别安排测试，执行时必须检查其对应断言：

1. 语音跨 120 秒读取边界且两侧有 padding：不丢失、不重复、时间仍落在真实音频内（任务 3）。
2. 旧 provider 与旧权重 revision 组合、以及 8bit 新模型漏写 revision：不能把旧 SHA / bf16 SHA 用到新模型（任务 7）。
3. 模型输出达到 token 上限或某个中间区间失败：整次失败，不能把部分段当成成功产物（任务 4、5）。
4. 推理缓存缺文件、tokenizer 带 `auto_map`、旧引擎仍已安装：禁止联网或远端代码，不回退旧引擎，也不能让体检误判可用（任务 4、5、7）。
5. 已有旧原稿的任务继续、Gateway 的严格逐段校正、旧 provenance 展示：不自动重转、不打乱段 id，不丢已有字段（任务 5、7）。
