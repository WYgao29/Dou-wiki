# Qwen3 ASR 单引擎替换实施计划

> **For agentic workers:** 用户已在开发过程中明确改为当前 Codex 独立实现、测试和审查，不再调用 Grok Build 或任何子 Agent。沿用已批准设计、此计划及现有 worktree，按 `superpowers:executing-plans` 接续；Task1–2 已完成，后续复用已有代码和证据。

**Goal:** 完成 Qwen3 的转写、分段和下游兼容验证，然后删除 SenseVoice 与 Whisper，最终只运行 Qwen3。

**Architecture:** SoundFile 流式读取最多 600 秒的识别窗口，Silero 判断全静音，Qwen3 先生成较完整的原文；30 秒局部锚点定位原文，ForcedAligner 对约 150 秒、硬上限 180 秒的窗口计算时间，再组织默认不超过 30 秒的展示段。本地规则完成文字规范化，固定架构适配层安全离线加载三份模型；沿用 `Transcriber` 及已有数据格式。

**Tech Stack:** Python 3.12、MLX、`mlx-audio==0.5.8` 基础包（先验证最小依赖）、SoundFile、Hugging Face 本地快照、pytest、现有 Service / Worker / Web / Gateway。

**Spec:** [Qwen3 单引擎替换设计](../specs/2026-10-07-qwen3-asr-design.md)。附件中的旧引擎保留条款已被用户明确覆盖，以该设计中的需求映射为准。

状态：2026-10-07 用户已批准方案，基准 `main@5a3ce45`，在 `codex/qwen3-asr` 开发。原 VAD 路径与共用 180/300 秒窗口的候选失败；固定 150 秒对齐原型通过两条文字质量与数值格式检查。展示[产品架构修订](../specs/2026-10-07-qwen3-asr-alignment-revision.md)后，用户回复“继续”，本计划已采用修订。任务 2 已通过实现与当前 Codex 审查；正式验收未完成，详见[可行性审查记录](../reviews/2026-10-07-qwen3-asr-feasibility.md)。

最小 ASR 环境不含 `sentencepiece` / `zstandard`，已安全加载固定识别、静音判断及对齐模型并完成两条原型转写。最终项目 extra / lock 已由任务 1 提交 `28030d5`；这些原型不能替代运行适配器的正式验收。

## Global Constraints

- 平台 Apple Silicon Mac Studio，64 GB 内存，Python 3.12；保留项目 `>=3.12,<3.14` 约束及现有非 ASR 功能。
- 最终只有 Qwen3；**任务 6 的删除前验收通过之前，禁止删除旧实现和旧引擎专用测试**。
- `TranscriptSegment`、`transcribe(audio_path, output_dir)`、artifacts 键、CLI/MCP 和 Web 路径保持兼容；provenance 只增加字段，旧记录不改写。
- 输入 16 kHz 单声道；最大时长 120 分钟；默认段上限 30 秒，允许配置范围 5–60 秒；静音/零采样返回空列表。
- 默认 bf16、Silero、对齐模型及 SHA、ITN 规则和错误分类采用规格中的精确值；ASR 不联网、不运行远端模型代码。
- 冷加载 ≤10 秒；包含读取/VAD/识别/锚点/对齐/ITN 的处理 RTF ≤0.1，冷调用另报含加载的总时间和 RTF；10 分钟端到端处理 ≤60 秒；内存必须实测，不把此前估计当成验收结论。
- 在仓库外独立环境安装和测试；现用仓库 `.venv`、真实 Vault、状态库、浏览器 Profile、oMLX 服务均不因计划或实验被改写。
- 真实测试只读既有素材并写测试 Vault；新素材下载、生产环境升级和旧缓存卸载不属于本计划的自动执行步骤。
- 用户已确认本次不做旧数据重转，先完成 Qwen3 替换；以后新增重转先补独立方案与计划。
- 本期不做热词、上下文提示和术语仓库；Qwen 生成参数为 `system_prompt=None`、`hotwords=None`，不新增提示配置、接口、记录或对比验收任务。

## Review Focus

以下条件已分别安排测试，执行时必须检查其对应断言：

1. 音频跨 600 秒识别窗口及共享对齐切点：样本只归属一个窗口，原文不丢字或重字；公开时间为合法整数毫秒（任务 3）。
2. 旧 provider 与旧权重 revision 组合、以及 8bit 新模型漏写 revision：不能把旧 SHA / bf16 SHA 用到新模型（任务 7）。
3. 模型输出达到 token 上限或某个中间区间失败：整次失败，不能把部分段当成成功产物（任务 4、5）。
4. 推理缓存缺文件、tokenizer 带 `auto_map`、旧引擎仍已安装：禁止联网或远端代码，不回退旧引擎，也不能让体检误判可用（任务 4、5、7）。
5. 已有旧原稿的任务继续、Gateway 的严格逐段校正、旧 provenance 展示：不自动重转、不打乱段 id，不丢已有字段（任务 5、7）。
