# 独立 AI 术语仓库与抖库热词接入方案

日期：2026-10-08。状态：方案草案，供审阅；本文不是已实施功能或部署记录。

## 目标与已确认要求

建立独立的术语仓库，先整理常用 AI 名称与概念，由人和 Agent 共同维护。抖库按视频内容选择相关词条，生成语音识别提示；其他工具以后可以读取同一份数据。

用户已明确要求独立维护、先覆盖 AI 内容，并制定 Agent 维护规则。2026-10-08 已确认：**核实来源且无歧义的新词可直接进入正式库；合并、删除和歧义词需要确认。**

推荐分两步交付：先完成可维护、可校验、可导出的词库，再接入抖库 ASR。ASR 是把音频转成文字的过程。校正阶段的术语参考、从校正结果发现新词另作后续扩展。本次只编写方案，仓库名称暂定 `ai-terms`；不据此创建新仓库、修改运行代码或启用提示。

## 存储选择与职责

| 方案 | 适用情况与代价 |
| --- | --- |
| **独立 Git 仓库：YAML 维护、JSON 导出，推荐** | 初期约百条术语；人和 Agent 可直接查看差异、核对来源和回退。通过校验与导出建立消费接口 |
| SQLite 主库 | 大量词条、复杂查询或多用户事务编辑时有价值；人直接查看和审阅修改需要额外工具 |
| 在线表格或编辑服务 | 适合多人通过界面编辑；需另外管理访问、导出与发布版本。当前没有这项需求 |

术语仓库负责词条、证据、维护规则和确定性导出。抖库负责按视频选词、组装模型提示、记录使用结果与效果验收。词库不保存用户 Vault、音轨、模型权重、浏览器资料或生产任务状态。

维护用 YAML，程序消费导出的 UTF-8 JSON。这样，抖库只读取数据文件，无需安装术语仓库的代码包，也无需在任务期间执行 Git 或联网拉取词库。维护规则通过仓库 `AGENTS.md` 指向正式文档，沿用维护机器已有全局约定，不复制本机全局规则正文。

建议目录如下。这里描述的是将来新仓库的目录，本次只保存本文。

```text
ai-terms/
  AGENTS.md
  README.md
  pyproject.toml
  topics.yaml
  terms/ai/<term-id>.yaml
  candidates/<candidate-id>.yaml
  observations/<observation-id>.yaml
  changes/<date>-<change-id>.md
  docs/schema.md
  docs/maintenance.md
  docs/export-contract.md
  scripts/check_terms.py
  scripts/export_terms.py
  tests/test_schema.py
  tests/test_export.py
```

每个词条一个文件，`id` 与文件名相同；展示名称和归类变化不导致编号变化。`observations/` 保存识别错误线索，`changes/` 保存需要确认的修改及决定。两者不进入识别用 JSON。导出物放在使用者指定的输出目录，不把临时音频和验收材料加入词条仓库。

## 词条结构与初始内容

每个 YAML 文件以 `schema_version: 1` 标明格式。正式记录包含以下字段：

| 字段 | 规则 |
| --- | --- |
| `id` | 稳定编号，匹配 `[a-z0-9]+(?:-[a-z0-9]+)*`；全库唯一，退役后不复用 |
| `canonical` | 来源支持的标准写法，1–80 个字符；保留原始大小写与标点 |
| `aliases` | 合法中文名称、简称和拼写形式；每项 1–80 个字符，可为空 |
| `category` | `company`、`model`、`product`、`tool`、`framework`、`concept` 或 `standard` |
| `topics` | `topics.yaml` 中已定义的主题，可多选；初始主题为 `ai.general`、`ai.models`、`ai.coding`、`ai.agents`、`ai.retrieval`、`ai.speech`、`ai.multimodal`、`ai.training` |
| `description` | 1–120 个字符的一句话说明，用于解释名称属于什么；不写营销评价或要求模型改写输出的指令 |
| `related_ids` | 人或 Agent 根据证据整理的相关词条编号，可为空；用于有限的一层扩展 |
| `sources` | URL、来源类型、核对日期与核对说明；正式词条至少有一个支持标准名称的第一手来源 |
| `status` | `active`、`candidate`、`retired`；候选放 `candidates/`，正式与退役记录放 `terms/` |
| `replaced_by` | 仅退役合并记录使用，指向保留词条；不得形成循环，最终指向正式词条 |

文本字段保持单行，不接受控制字符。日期使用带引号的 `YYYY-MM-DD` 字符串。来源类型为 `official_site`、`official_docs`、`official_repo` 或 `paper`；官网、官方文档、官方仓库和原始论文分别对应这些类型。候选可缺少已核实来源，但必须记录待核实内容。

示例用于说明格式；正式导入时仍按维护流程核对全部字段：

```yaml
schema_version: 1
id: qwen3-asr
canonical: Qwen3-ASR
aliases: []
category: model
topics: [ai.speech]
description: Qwen 团队发布的语音识别模型系列。
related_ids: []
sources:
  - url: https://github.com/QwenLM/Qwen3-ASR
    kind: official_repo
    checked_at: "2026-10-08"
    note: 官方仓库支持标准名称和语音识别用途。
status: active
```

第一批目标约 100 条，按实际视频中的使用频率安排。覆盖 AI 公司、模型家族、常用产品、编程与 Agent 工具、框架及技术概念。数量用于控制整理工作量，不为凑数纳入未核实名称；具体清单在建库阶段查第一手来源。

模型家族与具体版本分别建词条；没有必要使用的每个版本号不批量展开。别名只表示同一对象的合法名称。例如，某次转写出现的同音错字进入 `observations/`，不能因此加入 `aliases` 或自动替换规则。

正式词条的标准名称与别名按匹配规则检查跨词条冲突。共用的简称、同名产品和多义缩写进入候选处理；确认后通过唯一写法或更明确的限定名称解决，v1 不用一个模糊别名自动选中多个对象。家族简称不能同时无条件指向多个具体版本。

## Agent 维护规则

以下内容在建库阶段写入 `docs/maintenance.md`，由根目录 `AGENTS.md` 指向。

1. **读取已有数据再修改。** 检查标准名称、别名、编号和候选，确定是新对象、已有对象的别名还是识别错误。
2. **核对第一手来源。** 确认名称、对象类别和新增别名；记录 URL、日期及来源支持什么。视频、新闻和搜索摘要可提供线索，不能单独作为正式名称依据。
3. **按已确认权限操作。** 无歧义且来源充分的新词可以直接成为 `active`；来源不足或有歧义的记录成为 `candidate`。标准名称变化、已使用别名的重新归属、合并及删除属于影响消费者的修改，先提供具体差异和依据供确认。
4. **保留历史编号。** 用户确认删除后标为 `retired`；合并后保留旧编号及 `replaced_by`，不把旧编号分配给新对象。这里的删除表示退出新导出物，历史任务仍能读取原快照。
5. **验证并说明结果。** 格式检查、别名冲突、引用检查和导出检查通过后，说明新增或变更了什么、为什么、使用什么来源。普通新增由 Git 差异记录；需要确认的修改另存 `changes/` 决定记录。
6. **区分内容修改与使用版本更新。** 正式词条变化可以进入维护分支；发布新的数据文件和更新抖库所用版本是明确的后续动作，按该次任务授予的权限执行。一次词条更新不改变正在运行任务的提示。

校验脚本使用安全 YAML 解析和严格字段检查；它能证明格式、编号、引用和冲突符合约定，不能证明来源确实支持事实。来源核对是维护者需要提供的证据，不用一个自填的“置信度”数字代替。

## 导出与版本契约

`scripts/export_terms.py` 从干净且已提交的维护目录导出 `terms-v1.json`，包含 `schema_version=1`、`repository="ai-terms"`、完整 40 位 `source_revision`、`topics` 的编号到名称映射与按 `id` 排序的 `terms`。消费方按导出物中的主题映射校验词条，不在抖库代码中维护第二份主题清单。仅导出 `active` 记录；候选、退役、观察记录及维护说明不进入消费数据。

导出前完成全库校验：编号唯一、目录与状态相符、主题存在、来源完整、名称与别名无冲突、`related_ids` 指向正式词条、退役替代链没有循环。记录按固定字段序列化，字符串使用 UTF-8，JSON 键排序、缩进和末尾换行固定；相同提交导出字节一致。`checked_at` 表示实际核对日期，不在导出时自动改成当天。

对最终 JSON 原始字节计算 SHA-256，并在同目录写入 `terms-v1.sha256`，只包含校验值和数据文件名。SHA-256 是用于判断文件内容是否一致的摘要。抖库首次读取时核对相邻摘要文件、严格检查格式版本与记录，并记下实际文件摘要。未知格式、损坏文件或摘要不符明确报错；字段格式变化发布新 `schema_version`。

运行时从一个已发布的数据文件读取，不扫描正在编辑的 YAML。新的发布物采用新目录，准备完成后再更新使用者配置；读取获得不可变的任务内对象。首次建库还没有可发布提交时可校验和预览，但预览物不标成可供生产使用的发布物。

## 抖库选词与提示生成

### 配置与初版边界

推荐在 `[media]` 增加以下配置，保留未启用时的现有行为：

```toml
glossary_enabled = false
glossary_snapshot_path = ""
glossary_prompt_mode = "context"  # 可选 context / hotwords
glossary_max_terms = 20
glossary_max_prompt_chars = 1600
```

启用时必须指定本机数据文件；配置文件中的相对路径以该配置文件所在目录解析，不以 Worker 的当前目录解析。尚未冻结提示的任务在未启用时不访问词库路径；已冻结任务的重试规则见下节。数量上限与提示字符上限必须为正整数。20 条与 1600 字符是本方案建议的产品预算，不是上游模型限制；以实际验收决定是否调整。

选词不新增模型调用。首次只使用转写前已有的 `title`、`description`、`post_text`，重复文本去重；不根据作者名字猜领域，也不为了选词把当前 OCR 提前到转写前。这样无需调整现有采集顺序。

### 选择规则

1. 对匹配副本做 Unicode NFKC、大小写折叠与连续空白归一化，保留标准名称的展示写法。NFKC 用于统一全角、半角等等价字符。
2. 按字面查找标准名称与合法别名，名称内部的点号、连字符等不删除。含拉丁字母或数字的名称，匹配边缘不得继续连接拉丁字母、数字或下划线，例如 `GPT-4` 不命中 `GPT-40`；同一位置重叠的匹配先保留较长完整名称，避免短缩写命中另一个单词内部。其他名称按完整字符串匹配。单字中文与纯数字别名不进入正式库。
3. 标准名称直接命中优先于别名直接命中，再选择直接命中词条的 `related_ids`；只扩展一层，每个直接词条最多 3 个相关词，不遍历整类主题或整个 AI 词库。
4. 相同优先级先比较命中字段：标题、简介、正文；再按首次出现位置和 `id` 排序。相关词跟随其直接词条的顺序，重复编号只保留一次。达到词条或提示预算即停止。
5. 一个缩写无足够依据时不自动关联其他对象。标题只写泛泛的“AI”也不加载所有 AI 名称。没有命中时使用无提示转写，并记录 `no_match`。

匹配先后顺序、相关扩展上限和版本用 `selector_version="metadata-terms-v1"` 固定。同一数据文件、元数据、模式及预算必须得到相同选择和提示。v1 不根据未经校正的识别稿临时扩大热词范围。

### 提示模式

`context` 模式按固定模板生成“词汇参考：”及每条“标准名称：一句话说明”，传入 `system_prompt`，`hotwords=None`。`hotwords` 模式只传标准名称列表，`system_prompt=None`。两个模式用同一份选词结果起点，各自按实际最终字符串预算保留完整词条；不从中间截断一个名称或重复传入同一列表。

背景说明来自已核实词条，只解释名称，不推测视频结论或要求模型必须输出某个词。标题与简介用于选词，不原样作为执行指令放入模型系统提示。识别错误观察、来源 URL 和候选词不送给模型。

空列表时两个上游参数均为 `None`。`hotwords` 的字符统计按上游 `merge_hotwords` 的实际连接结果计算，`context` 按实际字符串计算。提示超出预算时从最低优先级末尾移除整条记录，记录被省略的数量；两个模式的真实音频验收分别报告最终使用的词条。

## 任务传递、恢复与兼容

抖库新增 `src/douyin_wiki/terminology.py`，负责消费数据校验、确定性选词与提示生成；不在模型适配器中查询 Git、编辑 YAML 或调用额外语言模型。

保留 `Transcriber.transcribe(audio_path, output_dir)` 现有两参数调用。为 `SelectedTranscriber` 与 `Qwen3Transcriber` 增加独立的 `transcribe_with_hint(audio_path, output_dir, *, hint)` 入口，`hint` 是包含实际提示与词库使用摘要的不可变对象。未启用或无命中仍调用原入口。启用且有命中时，如果自定义转写器不支持新入口，给出明确错误，不声称已使用提示。

Service 在元数据齐备且确实需要转写时冻结选词结果，并在推理前保存 `artifacts["asr_vocabulary"]`。记录包含状态、源提交、数据文件摘要、选词器版本、输入元数据摘要、预算、模式、选中词条的编号/名称/说明、最终实际提示及选择摘要。没有音轨时沿用 `transcript_skipped`，不创建一次虚构的提示使用记录。

该对象显式传入同步转写和 `recognize()`，并由任务内 `_WindowRuntime` 传到所有锚点定位、重试和异常修复的局部识别；不存成共享模型的可变“当前提示”。ForcedAligner 继续只对齐已经识别出的原文，词库不得替换用于对齐的源字符。

恢复语义如下：

| 情况 | 行为 |
| --- | --- |
| 新任务第一次进入转写 | 读取当前指定发布物，冻结选择与提示，然后执行识别 |
| 转写失败、尚无原稿，再次重试 | 复用已保存的实际提示；不因词库随后更新换一组词。记录不完整或版本不受支持时明确失败 |
| 已有 `transcript_raw` | 继续现有恢复流程，不调用 ASR，也不因词库变化改写来源记录 |
| 词库更新发生在识别窗口之间 | 当前任务的所有窗口仍用同一提示；以后首次进入转写的新任务使用新发布物 |
| 读取指定词库失败 | 启用情况下明确提示缺文件、摘要不符或格式错误；用户可修复配置或关闭词库。不能静默使用另一份词库 |
| 启用但没有相关词 | 保持无提示识别，记录所查版本与 `no_match` |

重试复用的冻结记录已经包含所需标准名称、说明和实际提示，因此不要求旧数据文件一直位于原路径。关闭开关或改预算影响尚未冻结的新任务；已冻结任务普通重试继续使用原提示。阶段 B 不新增针对已冻结任务重新选词的入口；修改该任务的元数据或提示后重新识别，纳入后续重转设计。

`media_provenance.asr` 增加 `glossary_source_revision`、`glossary_snapshot_sha256`、`glossary_selection_sha256`、`glossary_term_count`、`glossary_prompt_mode`、`glossary_prompt_chars` 的简短摘要。完整实际提示保存在上述任务记录，不重复送入每次 Gateway 请求。Gateway 协议 2 的 `provenance_keys` 同步保留这些字段；协议 1 沿用现有完整来源记录。这里的来源记录说明识别用了什么，不是视频事实的引用证据。

保持 CLI/MCP 工具名、Service 公开方法、Web 路径、`TranscriptSegment` 的编号/时间/文字格式和 Vault 格式兼容。保持当前语言、中文数字转换、600 秒识别窗口、180 秒对齐上限、展示段限制、离线模型加载与失败恢复规则。词库版本变化不自动重转历史视频。

## 后续：校正参考与新词反馈

此部分不进入前两步的开发验收，先记录方向。

让词库参与校正时，需要把同一个任务词汇参考送入 Provider 和 Gateway 两种路径；`local` 模式保持现有启发式行为。Provider 增加可选术语上下文，Gateway 协议 1/2 增加有界的 `terminology_context`，并让协议 2 的 `context_revision` 覆盖该新增输入。`context_revision` 是检查 Agent 提交是否基于当前材料的版本标识。

术语参考帮助判断名称写法，不能作为视频确实说过某个词的证据，也不能替代音频/OCR。校正仍保持段数、编号与时间；数字、金额和人名依据不足时保留原表述。

新词反馈从原稿、校正稿和校正记录提取候选，先进入 `observations/` 或 `candidates/`，附最小必要的错误片段与定位说明。一次校正变化只表示待核实线索；核实第一手来源、检查歧义和重复后，才能按已确认权限加入正式库。首版不自动读取或修改生产 Vault，也不把完整用户内容同步到可能共享的术语仓库。

阶段 A 的验证使用有实际意义的输入：重复编号、合法与冲突别名、候选缺来源、目录/状态不符、失效引用、退役合并循环、相同提交重复导出、未知格式和损坏摘要。网络核实结果与本地校验结果分别报告。

阶段 B 先写新增行为的失败用例，再实现并验证：默认两参数入口仍工作、名称词边界、全角与大小写、家族/版本区分、确定性预算裁剪、空命中、未知格式、任务间提示隔离、所有局部重新识别复用提示、失败重试保持原提示、已有原稿不重新识别，以及 Gateway 两个协议的来源字段。沿用 [Qwen 回归](../../../tests/test_qwen3_asr.py)、[分段回归](../../../tests/test_asr_segments.py)、[Service 夹具](../../../tests/test_service.py)和 [Gateway 上下文回归](../../../tests/test_gateway_context.py)；新增 `tests/test_terminology.py`。必要检查在独立环境执行，不同步现用 `.venv`。

真实效果验收使用已有两条参考音轨，再补 AI 名称、中英混说、普通非 AI 内容、同音歧义和没有命中词条的素材。素材使用执行阶段明确选择的现有文件；缺少某类素材时注明未覆盖，不把少量样本推广成全部场景有效。

每条音轨分别比较无提示、同批选词的纯热词和带说明的背景提示；记录实际词条、识别原文、最终展示稿、提示内容、整体字符错误率、目标术语正确率、非目标文字新增错误、对齐是否成功、耗时和内存。字符错误率即识别稿相对参考稿的字符编辑距离比例；评分算法、参考稿、数字规范化方式与模型版本在比较前冻结，各组一致。另保留人工逐项检查，不用词条替换后的分数代替真实输出。

启用条件：在选定验收集中，目标术语的总错误数低于无提示基线；各条素材的整体字符错误率不增加；没有新增会改变含义的非目标错误；全部时间、编号、窗口和恢复检查通过。热模型同素材重复三次比较，中位总耗时增加不超过 10%；内存单列实际变化，不能出现新增 OOM。若某种提示没有达到条件，保留测试结果并修改选词/提示规则或继续关闭功能，不预先宣布背景提示胜出。

代码验证按改动范围执行定向回归；接入完成后，通过 `UV_PROJECT_ENVIRONMENT` 显式指定仓库外已准备的独立环境，运行 `uv run --no-sync ruff check src tests`、`uv run --no-sync pytest -q -m 'not live'`，并记录准确环境和命令。真实音频验收单独执行，输出只写仓库外验收目录和测试 Vault，保存冻结输入、配置、数据快照摘要和比较报告。
