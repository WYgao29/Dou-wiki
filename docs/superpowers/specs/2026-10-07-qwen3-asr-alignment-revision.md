# Qwen3 ASR 识别与对齐方案修订

日期：2026-10-07。状态：用户在审阅修订问题后回复“继续”，已批准采用；权威设计与实施计划已同步。实施者仍为 Grok Build `grok-4.7 high` 子 Agent，代码审查仍由当前 Codex 负责。

## 为什么修订

原方案先把音频切到 30 秒内再识别，三组 VAD 参数都使两条素材的文字质量下降。把识别和对齐都限制为 180/300 秒，也没有同时保持两条素材的质量。完整上下文识别加短窗口对齐的原型则在两条素材上保留了原 Qwen 全文，独立复算原算法 / 统一算法距离分别为 **76 / 66**、**26 / 13**，与冻结基线相同，原文只少一个末尾换行。最终固定 150 秒对齐目标下，13/14 个展示段均不超过 30 秒，样本与字符覆盖完整。

120 秒对齐目标下，视频 2 处理为 40.86 秒，超过 39.70 秒目标。150 秒目标减少了一次锚点识别；发现的 40 ms 末端越界按模型 80 ms 时间栅格修正操作时间，原始预测和上游修正值保留。该固定方案已通过边界正反例及两条全轨回归，Codex 独立审查复算通过。处理耗时为 **29.77 / 38.19 秒**，RTF 为 **0.08050 / 0.09619**，physical footprint 峰值约 **10.77 / 10.87 GB**。

这些耗时包括读盘、识别、锚点、对齐与分段，尚不含 ITN。第二条计入热缓存模型加载的比值为 0.10153；不能据此宣称冷启动或正式速度验收通过。包含首次必要导入的模型初始化、10 分钟、2 小时及完整下游仍需产品实现后验收。原型先读整个输入再检查时长，不能复制为长音频实现。完整测量与审查见[可行性审查记录](../reviews/2026-10-07-qwen3-asr-feasibility.md)。

## 新处理流程

1. 继续接收 FFmpeg 生成的 16 kHz 单声道 WAV。用 `SoundFile` 流式读取，单个识别窗口最多 600 秒。较长文件在上限前的低能量位置切开；区间按实际样本索引连接，不漏读或重复识别。全静音与零采样仍返回空列表。
2. Qwen 先识别整个窗口，保留完整上下文；每个窗口独立使用 8192 token 预算。`temperature=0`、`batch_size=1`、默认语言 `Chinese`，不传热词、背景描述或上下文提示。内部音频块必须只有一个，耗尽预算使整次转写失败。
3. 每隔约 150 秒，用附近 30 秒音频的局部识别结果，在已生成的全文中找一个明确位置。这个位置称为锚点。局部结果只定位原文字符，不能替换整篇文字或修正术语；没有明确且唯一的匹配时失败。
4. 把匹配到的**原文**交给 Qwen3 ForcedAligner，利用实际预测的时间，在名义边界前后 15 秒内选择共享音频 / 字符切点。切点优先接近句读或停顿。150 秒目标与两侧最多 15 秒移动，使主对齐窗口最多 180 秒。
5. 主对齐窗口使用其对应的原文切片。保留原始预测、上游修正结果以及项目的边界处理记录；把对齐结果按原文字符组织为展示段，默认仍不超过 30 秒。标点与英文大小写保留，id 连续，不能丢字、重字、重叠或返回部分成功结果。
6. 按原规则执行确定性中文数字规范化。分段切点避开已识别的数词和版本表达，避免把「五点六」切成两段后不能转换。文字清理及规范化的正反例保持原要求。

识别窗口与展示段长度各有职责。`asr_segment_seconds` 继续控制展示段，范围仍为 5–60 秒；600/150/180 秒、锚点和匹配阈值作为已验证的内部参数，不增加界面调节项。

## 对齐与边界规则

使用 `mlx-audio==0.5.8` 的固定 ForcedAligner 架构与正常 `fix_timestamp` 后处理。该后处理有邻值替换和插值，因此不能把输出宣传为实测的逐字精确时间。[上游实现](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_forced_aligner.py)

匹配键只忽略标点、空白和大小写，保留与原文位置的映射，不执行数字、术语或「它/他」替换。锚点至少 40 个有效字符，编辑距离率不超过 0.12；存在不重叠且距离率在最优结果 +0.08 以内的候选时视为含糊。Unicode 大小写转换可能把一个字符展开为多个字符，映射必须保留正确的原文偏移。

上游时间修正位移超过 2000 ms 时失败。这个阈值用于拒绝已观察到的严重错误，尚不是经过独立标定的准确度指标；正式验收需要核对实际位置。固定模型的时间栅格为 80 ms。只有窗口末端不超过一格的越界，允许按实际样本末端限制操作时间；超过一格、负值、非有限数或倒序仍失败。原始和上游修正时间不改写，额外记录该次边界限制的原值、结果与幅度。

最终必须满足 `0 <= start_ms < end_ms <= duration_ms`、无重叠、文本非空、完整字符覆盖和连续 id。原模型首尾无声区无需被展示段覆盖；音频读取与窗口样本仍必须覆盖整条输入。不用字数比例估算时间，不制造置信分数。

| 静音判断 | `mlx-community/silero-vad` | `7bc17f22d3c0451bd3a6cd71e759b009271ff49a` |
| 对齐 | `mlx-community/Qwen3-ForcedAligner-0.6B-8bit` | `0e1a68e91d815300c7c9754b2a7639378b23db15` |

对齐权重为 1271924386 字节，SHA-256 `be19ef8ac4326d032e7673342930b14c2df30bd68c1632493b0f563e30829f91`，Apache-2.0，已在授权实验中准备。沿用已验证的基础依赖，不新增官方 `qwen-asr`、vLLM、独立 `silero-vad`、`sentencepiece` 或 `zstandard`。Qwen 所需的 `WhisperFeatureExtractor` 是音频预处理器，保留它不代表保留 Whisper 识别引擎。

新增 `alignment_model`、`alignment_model_revision`，并在诊断中检查对齐快照。固定架构、safetensors、拒绝 `auto_map`、`trust_remote_code=False`、本地离线、量化先于键检查及严格加载仍按原安全规则。缺少模型明确失败并给出准备命令，运行时不自动下载。

中文与中英混合是本期实测范围。其他语言须同时满足识别与对齐器的支持条件；缺少所选语言分词依赖时明确报错，不把识别器的语言列表当成对齐保证。默认不增加其他语言包。

## 运行与数据兼容

`Transcriber.transcribe()`、`SelectedTranscriber`、`TranscriptSegment`、Service、CLI/MCP、Web 路径及 Vault 格式保持原契约。Runtime 同时惰性加载识别、静音判断与对齐模型，使用一把锁保护初始化和整次任务；doctor 和构造器不加载模型。

provenance 增加对齐模型 / revision、识别窗口、对齐方案、时间戳类型及边界限制摘要。旧 provider、旧稿、校正稿和历史 `fallback_reason` 继续可读，不重写旧记录、不自动重转。异常分类、清理后重试、下一条任务可运行和不回退旧引擎均按原要求。

## 原实施计划的变更范围

仍按原 8 项任务执行，原删除顺序与最终验收门不变。

| 任务 | 修订 |
| --- | --- |
| 1 依赖与可行性 | 补入对齐器和上述实验记录；可行后提交同一个最小依赖 extra / lock |
| 2 文字规范化 | 原正反例不变；任务 3 复用转换规则提供数词区间及已有数字保护，避免跨段破坏数值 |
| 3 音频分段 | 改为最多 600 秒的流式识别窗口、原文字符映射、锚点匹配及对齐结果组段；验证 Unicode、重复句、数词边界、末端一格处理和严格覆盖 |
| 4 Qwen 适配器 | 增加安全对齐加载与调用、每阶段预算、完整任务锁及失败清理；旧引擎继续保留到正式验收 |
| 5 诊断与下游 | 检查三份模型和新 provenance 字段；旧记录与任务继续行为保持原要求 |
| 6 删除前验收 | 用生产适配器重新测两条素材、ITN、速度、10 分钟、2 小时、内存、离线和下游；按实际音频核对定位，所有必需项通过才删除旧引擎 |
| 7 迁移与删除 | 新增对齐配置默认值；原迁移、安全读取及旧实现 / 专用依赖删除要求不变 |
| 8 清洁环境与交付 | 没有旧引擎依赖的独立环境重新验收、检查发行包并更新最终文档 |

速度目标仍为含读取、识别、锚点、对齐和 ITN 的处理 RTF ≤0.1；10 分钟端到端 ≤60 秒，冷模型加载 ≤10 秒。按原需求，在本地模型已缓存的条件下，冷加载从首次必要导入计时到三份模型可用；系统文件缓存状态另行记录。冷调用同时报告含初始化的总时间，10 分钟验收不扣除加载。内存、定位、2 小时和下游均须实测，不能用本次原型代替。缺少完整视频时按原计划注明未覆盖的抽帧检查，使用已有帧 / OCR 材料完成能验证的下游流程。

热词、上下文提示、独立术语仓库及旧视频重转仍不在本期。生产服务、主仓库现用环境、真实 Vault 和已安装模型缓存不因本修订自动更新；这些边界沿用原授权。
