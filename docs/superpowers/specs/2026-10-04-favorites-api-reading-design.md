## 1. 目标与现有问题

让现有 Web、CLI 和 MCP 能识别当前登录账号的收藏夹目录，以真实收藏夹 ID 读取指定夹内作品，并继续使用现有选择、确认和采集流程。

`adapters/favorites.py` 当前从 `#semiTabPanelfavorite_folder` 等节点读取链接与 `data-folder-id`。实测该面板是空容器，实际目录位于其他节点，收藏夹卡片也没有暴露适配器期待的稳定 ID。因此账号已经登录时，现有 MCP 目录清点仍返回空目录与“不完整”提示。

本轮替换收藏夹目录与指定收藏夹的读取方式。`folder_ids=None` 的“全部收藏”继续读取账号级作品列表，包含未分组作品，不主动遍历所有收藏夹；其现有 DOM 作品列表读取保留。目录读取修复后，全部模式可展示真实目录，但不能据此声称作品归属已补齐。

不增加自动同步、默认批量导入、下载或模型调用；不调整收藏导入业务、数据库表、Vault 格式或其他媒体适配器。

## 3. 路线选择

| 路线 | 能解决的内容 | 代价与判断 |
| --- | --- | --- |
| 网页原生 API 请求环境＋原始响应读取 | 获取目录 ID、夹内作品和分页信息；沿用登录与网页签名 | 推荐；主动调用与分页必须先验证 |
| Python 直接请求并自行实现签名 | 可直接分页，减少页面依赖 | 需要维护签名、浏览器指纹和安全 SDK 参数；本轮不引入 |
| 只修 DOM 选择器 | 可能恢复名称和画面数量 | 当前卡片缺少稳定 ID，无法独立解决指定夹与分页；不作为目录回退 |

两个目标端点均为同源 GET：

- `/aweme/v1/web/collects/list/`：目录，分页参数为 `cursor`、`count`。
- `/aweme/v1/web/collects/video/list/`：夹内作品，另有 `collects_id`。

源码参考：[douyin-downloader 请求实现](https://github.com/jiji262/douyin-downloader/blob/main/core/api_client.py#L1198-L1215)、[F2 目录字段解析](https://github.com/Johnserf-Seed/f2/blob/v0.0.1.8-pw3/f2/apps/douyin/filter.py#L453-L544)、[douyinmind 网页原生函数调用](https://github.com/MQTQW/douyinmind/blob/master/backend/app/services/douyin_collector.py#L200-L284)。这些项目证明实现方向，不替代本仓库的行为验证。

首阶段验证网页原生 API 函数桥：以端点字符串识别当前网页模块及只读导出函数，不硬编码模块编号或压缩后的导出名；目录调用 `{cursor, offset: count}`，夹内调用 `{collectsId: folder_id, cursor, offset: count}`。这组参数已由首阶段主动跨页实测确认。只能调用已明确对应这两个 GET 端点的函数，不能试调用未知导出函数。

原生函数仅负责发出请求，不消费其转换后的返回对象；Python 从匹配的网络响应读取原始字节。不得修改已签名 URL 的 cursor 后重放，也不能把复制 Cookie 的普通 HTTP 请求当作等价实现。若函数桥不能完成主动请求与翻页，保持本阶段为未通过，修订设计后再接入，不能靠首屏预取伪装完成。

## 4. 模块与数据流

新增两个职责明确的内部模块：

| 文件 | 职责 |
| --- | --- |
| `adapters/favorites_api.py` | 原始 JSON 解码、字段与类型校验、目录和作品归一化；不启动浏览器、不持久化 |
| `adapters/favorites_browser.py` | 响应监听、网页只读函数桥、请求与响应关联、超时与监听清理；不写业务检查点 |
| `adapters/favorites.py` | 现有 Profile 锁和生命周期、账号保护、目录和指定夹分页、跨夹去重、完整性与检查点；全部收藏继续走已有作品列表链路 |

数据流为“已有 Profile 锁 → 同一浏览器页面 → 安装响应监听 → 打开收藏页 → 读取目录 → 验证所选 ID → 逐页读取指定夹 → Python 归一化 → await 现有检查点 → 下一页”。整个清点串行执行，不新建第二个常驻浏览器、授权入口或服务。

监听先于导航与主动请求安装，按同源、完整路径、GET 方法、收藏夹 ID、请求 cursor 与 count 关联响应。忽略无关请求、其他夹预取、过期响应及已关闭读取器的回调。初始页响应可以复用，但不能把网页预取当作后续分页能力。

`directory_only=True` 只产出目录，不主动请求夹内作品，不写作品检查点；网站自身预取不进入返回清单。指定多个 ID 取并集，每件作品保留全部已确认归属并按作品 ID 去重。目录不完整时，已经可靠识别的所选 ID 可继续读取并保留提示；未知 ID 沿用拒绝行为，不按名称猜测。

## 5. 原始字段与作品类型

原始响应在 Python 使用 `json.loads(bytes)` 解码。收藏夹优先取 `collects_id_str`，缺失时只允许原始 JSON 的整数或 ASCII 数字字符串；不接受布尔值、浮点数、指数表示、名称或超过 32 位的 ID。作品 ID 同样保持十进制字符串，不能经过 JavaScript Number。字符串 ID 与整数 ID 冲突时该记录不可信，清点不完整。

目录映射：`collects_id_str/collects_id → FavoriteFolder.id`，`collects_name → name`，每夹 `total_number → reported_count`；响应顶层 `total_number` 是目录数量，不能当成作品数量。

作品映射到现有 `FavoriteWork`：稳定 ID、规范抖音 URL、描述标题、作者、`folder_ids` 和 `available`。视频需要明确视频结构；静态图文依据已有 `images` / `image_post_info.images` 结构；文章需要明确文章规范路径或已核实的文章判别证据，继续保留在清单中并标为暂不支持。不能仅凭未知 `aweme_type` 的缺省值认定视频。

无法识别类型但有可信作品 ID 的记录以该 ID 的规范 `/video/` 地址保留占位，设置 `available=False`，记录“作品类型无法确认，未纳入导入选择”的提示，并令结果不完整；该地址不证明它实际是视频。无法识别稳定 ID 的记录不编造 ID，保留已识别记录并提示清点不完整。

不新增公开 `source_kind` 或持久化字段，不把响应中未出现的失效作品补成虚假条目。标题、作者与可用性取采集样本中实际存在的字段；本次真实验收只覆盖视频，图文与文章的离线覆盖不能写成真实账号端到端通过。

## 6. 分页与完整性

默认主动请求 `count=20`；目录与每个所选夹最多各读取 500 页。超过上限返回保留已发现数据的不完整结果。cursor 在内部保持字符串，不推算下一页；只使用响应实际返回的 `cursor` 或 `max_cursor`。

成功页要求 HTTP 200、明确的成功 `status_code=0`、符合类型的列表字段和明确的 `has_more`。`has_more` 接受布尔值、整数 0/1 或字符串 `"0"`/`"1"`；缺失不表示结束。只有成功页的明确结束信号可确认分页完成。`has_more=true` 时 cursor 缺失、保持不变或循环，目录空页仍称有下一页，以及达到上限，均停止并返回不完整结果，不能无限滚动或把错误当空列表。

真实验证修订：时尚夹每页 2 件时，cursor `2` 返回 `aweme_list=null`、`has_more=1`、下一 cursor `4`；继续读取 `4/6` 后取得其余三件，与 Chrome 四件一致。夹内列表为空或缺失，但成功状态、下一页标志和 cursor 推进可信时，保留不完整提示并继续读取后页；不把 null 当作可信空清单。循环与 500 页上限仍终止。证据见仓库外 `fashion-active-result.json`。

目录按 ID 去重；作品按 ID 去重并合并所选夹归属。目录数量与实际不同，或有不可解析目录记录时，`folders_complete=False`。一份目录完整只表示收藏夹列表完整，不表示每夹作品数量相符。

指定夹的作品数量与目录 `reported_count` 不一致时，保留已读作品，`complete=False`，提示“收藏夹「{name}」显示 {reported} 条，实际读取 {observed} 条，数量不一致”。“时尚”7/4 即使 `has_more=0`，仍应得到这个结果；`folders_complete` 可以为 True。沿用现有 `accept_partial=True` 确认要求，不自动放行，也不猜测少掉的 3 条。

全部收藏模式的 `complete` 只针对账号级作品清单；无法确定归属时继续提示。未选择的夹的预取数量差异不能污染所选范围的完整性。

全部模式读取目录时遇到一般接口/协议错误，保留目录提示与 `folders_complete=False`，继续现有账号级作品列表清点；不能让新目录链路阻断此前可用的全部收藏。明确登录失效或账号变化仍中止。目录-only 和指定夹模式则需要可信目录，不能用 DOM 名称绕过稳定 ID 校验。

## 7. 登录、账号、错误与恢复

继续使用 `_locked_profile()` 与 `_launch_options()`，确认既有 Cookie 可用及页面没有登录阻挡；初次页面加载时账号字段可迟于旧 750ms 等待出现，因此最多等待 20 秒至既有身份解析就绪；明确登录阻挡仍直接报错。清点中每次发布检查点前核对同一账号。不能从收藏夹所有者字段推断当前登录账号，因为目录可能存在关注的他人收藏夹。

本次旧目录任务还暴露了账号回退解析把旁边年龄拼进抖音号的问题。本轮限定修正 `_ACCOUNT_SNAPSHOT_JS` 的回退文本边界：只从包含“抖音号”的最小可见文本节点读取，不解析整个祖先的连续 `textContent`；保持既有 ID 优先顺序与前缀。旧批次保存的错误 ID 不按后缀自动修复或合并，必要时新建批次；不直接修改历史数据库。

明确登录失效、验证码阻挡或账号变化抛出 `BrowserAuthRequiredError`，由现有流程进入授权等待；本方案不自动完成验证码。单独 HTTP 403、429 或错误响应不能一律解释为未登录。

每次页请求总预算 20 秒。超时、429、5xx 最多重试 2 次，退避 1、2 秒，重试仍计入总预算；明确签名/安全 SDK 拒绝、无效 JSON、错误协议或账号变化不循环重试。目录-only/指定夹模式在首个可信结果前失败，沿用 `ExternalToolError`；已有可信目录或作品后获取失败，返回保留数据的不完整结果与具体提示。全部模式的目录失败按上一节处理。任务取消、租约失效、检查点写入失败继续抛出，不转成成功或普通分页提示。

每个有效页先 await 已有 `on_checkpoint`，再读下一页；恢复重新从首 cursor 开始，复用现有去重、增量基线与历史保护，不新增分页游标表。响应回调只交付数据，不异步直接写入检查点；离开页面或取消时移除监听并收拢相关任务。

日志只保留端点路径、状态、页号、计数和必要的资源 ID，不记录完整请求 URL、Cookie、签名、认证头或原始用户响应。

## 8. 项目约束

- Python 支持范围保持 `>=3.12,<3.14`，不新增依赖或新的持久化表。
- MCP 工具名称与参数语义、CLI 命令与别名、Service 公开方法、Web 路径与负载、状态码、静态资源 URL 和 Vault 格式保持兼容。
- 清点仅读取目录与作品元数据；下载、转录、模型分析和入库继续由用户确认后的既有子任务执行。
- 全部收藏仍包含未分组作品，不主动遍历所有收藏夹；指定多个收藏夹取并集，以作品 ID 去重并保留已确认归属。
- 数量不一致或无法证明分页完成时保留已发现作品，标记不完整，并沿用明确接受不完整清单的确认要求。
- 本机服务引用仓库 `.venv/bin/python`；不移动或盲目同步现用环境。开发与安装验证使用隔离环境；不直接编辑用户 Vault、状态库或原浏览器 Profile。
- 本次不授权发布、重启服务、切换真实客户端配置或批量导入。首次只读实测的授权覆盖同范围开发验证；出现需要用户处理的登录或验证码时再说明具体阻塞。
- 默认由当前 Agent 执行。使用 Superpowers 不授权子 Agent；委派须用户明确要求。

## 9. 验收与交付

当前真实账号基准是目录 4 个、可访问作品 15 个；“时尚”7/4 应被保留为不完整提示。正式真实验证应使用当次实际状态，不能永久硬编码个人收藏夹名称、ID 或作品数为产品测试要求。只读验收不创建采集子任务，不宣称下载、图文、文章或完整入库已经端到端通过。

当前公共操作说明继续以 [收藏批量导入](../../favorites-import.md) 为准。实现完成后更新其读取机制、数量差异与验证边界；浏览器验证只针对收藏页与确认控件，不扩大到其他 UI 或发行流程。回退以开发提交为单位，用户已有任务、选择与知识内容保留。
