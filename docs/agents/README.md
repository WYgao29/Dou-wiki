# MCP 自助接入入口

本目录提供与客户端无关的接入规范。外部 Agent 读取本入口后，识别自身客户端能力，将通用参数转换为客户端支持的配置，在仓库外完成配置和验收。项目不维护客户端注册表、专用适配代码或每个 Agent 的生效配置。

| 文档 | 职责 |
| --- | --- |
| [自助配置步骤](self-setup.md) | 探测、外置配置、规则加载、验证、重入与回退 |
| [接入参数与验收契约](integration-contract.md) | 路径参数、STDIO 启动模板、外部目录和结果格式 |
| [Gateway Agent 接入指南](../gateway-agents.md) | 唯一共用业务规范：工具角色、调用顺序、确认条件和事件接续 |

先读取前两份文档，再加载 Gateway 指南。客户端字段和配置位置由接入 Agent 按本机客户端版本查明，不照搬其他客户端的格式。连接 MCP 不表示客户端会自动读取本目录、根 AGENTS.md 或服务端 instructions。

| 对象 | 规则入口 |
| --- | --- |
| 仓库维护 Agent / 开发者 | [根 AGENTS.md](../../AGENTS.md)与[项目结构](../architecture.md) |
| 外部 MCP 查询、采集或分析 Agent | [Gateway 调用规范](../gateway-agents.md#调用边界与多客户端)及其中的工具顺序、确认条件和事件接续 |
| 用户 Vault 中的知识库文档 | 应用生成的 Vault AGENTS.md；不作为源码维护指令 |

## 文件边界

| 位置 | 内容 |
| --- | --- |
| 项目仓库 | 由维护者管理的通用文档和参数示例；接入 Agent 只读 |
| 客户端原生用户配置目录 | MCP 注册、工具限制和指令加载设置；必须在仓库外 |
| 仓库外独立实例目录 | 工作文件、日志、配置备份、规则加载快照、重试状态和验收记录 |
| 仓库外 Vault | 通过 MCP 产生的知识库数据；权限按角色和既有授权确定 |

接入 Agent 不在仓库内创建 `.mcp.json`、`.agents/`、客户端说明、脚本、日志或测试 Vault，也不修改源码、测试、依赖、Git 或现用 `.venv`。启动命令可以指向仓库已有解释器，但工作目录在仓库外，并禁用 Python 字节码写入。仓库中不建立 `clients/` 目录，客户端差异记录在自己的外部验收文件中。

## 给接入 Agent 的指令

用户可将下面的指令交给任意具有本地配置能力的 Agent，并替换仓库路径：

```text
读取 <REPO_ROOT>/docs/agents/README.md，按其中的自助配置步骤接入抖库 MCP。
自行核对当前客户端的版本、配置格式和规则加载机制，将实际配置及所有运行文件放在仓库外。
项目仓库只读，不在其中安装依赖或生成客户端文件。先使用隔离 Vault 验证。
未指定角色时按查询角色配置；已有授权沿用，不自行扩大数据写入范围。
完成后给出配置位置、已验收能力、能力限制和回退方法，不将连接成功等同于完整流程验收。
```

框架默认使用当前已有的 MCP STDIO 服务。缺少 STDIO、本地配置或必要权限时，接入 Agent 记录缺失能力并报告；不能通过修改项目代码补足。客户端原生配置和规则加载需实际生效，目录划分及提示词不提供服务端鉴权或任务排他领取。
