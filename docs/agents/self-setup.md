# Agent 自助配置步骤

本流程由接入 Agent 执行，适用于支持本地 MCP STDIO 的客户端。复用现有抖库配置和用户已有授权，开放全部 MCP 工具；源码由 Codex 维护，客户端配置及运行文件放在仓库外。参数及模板见 [接入契约](integration-contract.md)，工具流程及任务接续见 [Gateway 指南](../gateway-agents.md)。

## 1. 读取规范并识别能力

读取本入口、契约和 Gateway 指南，检测当前客户端名称、版本、实际用户配置目录及配置 schema。优先使用客户端本身的 CLI、帮助或官方文档，不把其他客户端的字段当作通用格式。

核对本地 STDIO、启动环境、仓库外工作目录、全部工具加载及指令加载方式，并确认客户端能在当前任务中连续调用工具。只有任务需要在对话结束后继续执行时，才核对客户端的自动续跑、会话心跳或后台投递能力；没有这类能力不妨碍当前任务内持续跟进。缺少完成目标所必需的能力时报告具体限制，不编写项目源码适配器。

## 2. 解析路径和授权范围

从文档位置确定 `repo_root`。在客户端自身用户数据目录下选择或复用独立的 `external_root`，解析原生配置、Vault、Profile 和所有写入目标，按契约确认均在仓库外。仓库只作为文档和已安装包的读取来源。

从已安装服务或已有 MCP 实例读取实际的配置路径、Vault 和已登录浏览器 Profile，直接复用。用户授权使用抖库后，默认开放全部 MCP 工具，按用户任务及已有授权执行，不逐项重复索要许可。只有无法确定目标或确实缺少必要输入时才询问。客户端实例的 `gateway` 持久保存，重启不换标识。

接入期间不修改仓库源码、项目配置、依赖或 Git 状态，不在其中执行安装、构建、`uv sync` 或生成客户端文件，也不修改仓库权限。所有技能、脚本、日志、状态和临时文件放在仓库外。

## 3. 选择已安装启动环境

选择已能导入 `douyin_wiki` 的 Python，并在仓库外工作目录用 `-B` 核对其版本、包版本和实际模块来源。解释器需满足项目当前 Python 范围；确认其加载的是与本项目文档对应的安装，不能仅凭命令名称选中另一份旧包。

优先复用已有解释器。环境缺失时报告安装前提，不在源码仓库中生成或同步 `.venv`；需要新环境时在用户授权的仓库外位置按安装文档处理，不能改动现用服务的环境。

读取并验证已有 `config.toml`，确认文件存在、能解析且 `vault_path` 是目标知识库的仓库外绝对路径。使用契约中的 STDIO 启动参数，显式传入已有配置和已登录 Profile，不另建配置或浏览器目录替代现有目标。

## 4. 写入客户端原生配置并加载规则

先读取原生配置；已有同项目接入时核对后复用，只修正需要变化的字段。配置需要改动时在外部 `backups/` 保存原文件及 SHA，按当前客户端 schema 合并抖库条目，保留其他 MCP server、指令和用户设置。客户端只支持仓库内项目配置时，不创建该文件，记录缺失的外置配置能力。

开放 `tools/list` 返回的全部 MCP 工具，不设置查询角色或采集角色白名单。客户端要求显式工具列表时，填写实际返回的完整清单，并在服务升级后更新；不固定工具数量。客户端另有 MCP 工具授权策略时，同样允许本服务的全部工具，沿用用户授权，不新增逐项审批。全部工具可用后，按用户任务和已有授权调用。

用客户端实际支持的机制加载共用 Gateway 规则：能引用文件时引用其绝对路径；只能内联时在外部 `rules/` 生成加载快照并记录来源路径及 SHA。核对实际注入位置或客户端加载结果，不能仅保存文件或一个 Markdown 链接。客户端旧技能或提示词中若有工具白名单、逐项审批或返回 `job_id` 后停止的规则，按本指南更新，避免继续加载旧规则。

## 5. 核对连接和任务执行

通过实际客户端执行 MCP `initialize`、`tools/list` 和基础查询，核对客户端可用工具与服务返回的完整清单一致，并确认当前 MCP 进程使用目标配置、Vault 和 Profile。单独启动的 CLI 探针不能代替当前连接的目标证据。核对规则已加载，结果记录在仓库外。

有用户提交的采集任务时，按 Gateway 指南在同一任务中查询简短状态和事件，完成校正、分析、结果回复及事件确认，记录实际通过的流程。先核对 `get_job` 的 schema，支持 `gateway_protocol=2` 时显式传 `2`；旧服务以事件为主要等待入口，必要时才读取完整任务。`job_id` 是中间回执，不代表任务完成；不要求用户再发一次检查指令。任务完成（含提示）、失败或取消并交付结果后停止跟进，取消后不自动重试。核对 Worker 使用同一 Vault 和 Profile。未实际执行的业务流程记录为未验证，不为了验收自动执行无关写入操作。

多个实例只处理分配给自身 `gateway` / 会话的事件，不确认其他实例事件。当前任务内的等待、轮询及失败重试按 Gateway 指南执行。需要在对话结束后自动接续时，优先使用客户端已有机制，无需额外常驻监控器；只有选择自建事件桥时才配置对应监控。相关脚本、定时器配置或状态文件仍在仓库外，后台能力单独记录。

接入前后用只读文件清单、mtime 或内容 SHA 核对仓库，没有本次接入生成的文件或修改；清单本身放在外部目录，不运行仓库 Git 命令。发现未知变化时报告路径，不自动删除或还原他人的内容。

## 6. 记录结果和切换目标

按契约填写外部 `integration.json`：客户端与版本、实际配置位置、规则加载、完整工具清单、独立标识、检查结果、限制及回退方法。不创建仓库内客户端条目或专属文档。

新连接直接使用已确认的现有目标。只有复用的连接与目标不一致，或用户要求更换目标时，才按以下顺序重建本实例连接；不额外设置授权步骤。

1. 读取并验证已存在的目标 TOML，核对 Vault 与已登录 Profile 均在仓库外。Profile 由 `DOUYIN_WIKI_BROWSER_PROFILE` 单独指定，需与 `DOUYIN_WIKI_CONFIG` 一起核对。
2. 暂停本实例的监控和新任务派发，等待在途调用结束，关闭本实例的 MCP 连接并确认旧 STDIO 进程已退出。现有服务在首次业务调用后缓存配置；修改文件、客户端设置或对旧进程再次 `initialize` 都不会清除该缓存。不要停止其他实例或系统现有 Worker。
3. 按步骤 4 备份并合并客户端设置，以目标配置、Profile、仓库外 cwd 和禁用字节码的环境启动新的 MCP 进程，重新执行 `initialize`、`tools/list` 并核对开放工具和规则加载。不能确认旧进程退出或不能启动新进程时，记录阻塞，不继续派发任务。
4. 从客户端实际启动记录或进程信息确认新进程使用目标环境，核对 Vault、Profile 和状态库路径，再读取已知条目或 job 验证归属。配置文件已修改或一次空查询都不足以证明当前进程已切换；重新检查受变化影响的能力。
5. 使用监控时，将其环境同步到同一目标并复核后再恢复；同时核对 Worker 的 Vault / Profile。更新 `integration.json` 中的实际结果。失败时报告限制或按步骤 7 回退。

客户端配置回退不撤销已发生的知识库数据操作。

## 7. 重入、升级和回退

重复接入时从外部验收记录恢复参数，复用配置和实例标识，不新建重复条目或每次更换工作目录。客户端版本、文档来源 SHA 或启动环境变化时重新检查受影响的配置和能力；配置、Vault、Profile 或启动环境发生变化时，按步骤 6 重建连接并复核目标。后台状态按既有事件语义恢复，不跨轮保存会跳过失败事件的高水位。

回退时暂停本实例监控和派发，等待在途调用结束，关闭连接并确认旧 STDIO 进程退出；核对修改后的配置仍匹配本次记录，再恢复其外部备份或移除本次新增条目，保留其他客户端配置。恢复已有连接时，以原配置及 Profile 启动新进程，按步骤 6 复核目标和监控后恢复派发，不能只还原文件。只清理确认由本次创建且已无用途的外部临时文件，保留必要验收和恢复材料。项目代码、Git、服务环境及他人工作区不作为接入回退目标。
