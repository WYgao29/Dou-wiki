# Agent 自助配置步骤

本流程由接入 Agent 执行，适用于支持本地 MCP STDIO 的客户端。输入为项目文档及用户已有授权；输出为仓库外的生效配置和实际验收记录。参数及模板见 [接入契约](integration-contract.md)，工具流程及确认条件见 [Gateway 指南](../gateway-agents.md)。

## 1. 读取规范并识别能力

读取本入口、契约和 Gateway 指南，检测当前客户端名称、版本、实际用户配置目录及配置 schema。优先使用客户端本身的 CLI、帮助或官方文档，不把其他客户端的字段当作通用格式。

核对是否支持：本地 STDIO、指定启动环境、仓库外工作目录、加载文件或内联指令、工具范围限制，以及所选角色需要的后台续跑和原会话投递。查询角色不要求采集或后台投递能力。无法满足必要能力时记录 `blocked`；可以完成部分用途但无法强制限制时记录 `limited`，说明实际边界。不要编写项目源码适配器。

## 2. 解析路径和授权范围

从文档位置确定 `repo_root`。在客户端自身用户数据目录下选择或复用独立的 `external_root`，解析原生配置、Vault、Profile 和所有写入目标，按契约确认均在仓库外。仓库只作为文档和已安装包的读取来源。

未指定角色时使用查询角色和独立测试 Vault；不自动升级采集或写入权限。已有用户选择和授权可以复用，不重复索要；缺少会影响真实数据范围的输入时，先完成隔离验证再报告待补输入。客户端实例的 `gateway` 持久保存，重启不换标识。

接入期间不运行仓库 Git 命令、安装、构建、`uv sync` 或测试脚本，不创建仓库内客户端配置、`.test-*`、`.superpowers`、日志和状态文件，也不修改仓库权限来影响已有服务。维护者执行项目开发验证属于另一职责。

## 3. 选择已安装启动环境

选择已能导入 `douyin_wiki` 的 Python，并在仓库外工作目录用 `-B` 核对其版本、包版本和实际模块来源。解释器需满足项目当前 Python 范围；确认其加载的是与本项目文档对应的安装，不能仅凭命令名称选中另一份旧包。

优先复用已有解释器。环境缺失时报告安装前提，不在源码仓库中生成或同步 `.venv`；需要新环境时在用户授权的仓库外位置按安装文档处理，不能改动现用服务的环境。

按契约生成隔离 `config.toml`，确认文件已存在、能解析且 `vault_path` 是仓库外绝对路径。使用契约中的 STDIO 启动参数及环境，避免默认配置回落到真实 Vault。

## 4. 写入客户端原生配置并加载规则

先读取原生配置；已有同项目接入时核对后复用，只修正需要变化的字段。配置需要改动时在外部 `backups/` 保存原文件及 SHA，按当前客户端 schema 合并抖库条目，保留其他 MCP server、指令和用户设置。客户端只支持仓库内项目配置时，不创建该文件，记录缺失的外置配置能力。

工具范围从 Gateway 指南的角色表和所需业务流程取得，并与服务返回 schema 核对。默认不开放整份工具清单，不将提示词约束当作强制权限过滤。业务写入仍遵守原有确认条件。

用客户端实际支持的机制加载共用 Gateway 规则：能引用文件时引用其绝对路径；只能内联时在外部 `rules/` 生成加载快照并记录来源路径及 SHA。核对实际注入位置或客户端加载结果，不能仅保存文件或一个 Markdown 链接。检查是否接收服务端 instructions，但它不能代替本地调用边界和角色限制。

## 5. 验证所选角色

先通过 MCP `initialize` 和 `tools/list`，再在隔离 Vault 调用 `search_knowledge`，使用不匹配测试词并核对返回结构。服务工具清单与客户端最终开放的清单分别记录，不能用服务注册了某工具证明客户端过滤已经生效。核对规则加载和文件路径边界，结果写入外部验收记录。

查询通过后，采集 / 分析角色还须在已授权的素材与模型消耗范围内验证 job、当前 phase、提交、失败不确认、成功后确认和原会话路由。确认目标 Worker 使用同一 Vault 和 Profile；不要为隔离测试改系统现有 Worker 或 LaunchAgent。无法验证后台任务或投递时，记录该能力尚未验收，不自动切换真实数据。

多个实例只处理分配给自身 `gateway` / 会话的事件，不确认其他实例事件。无模型监控使用现有 MCP 分页接口，或在外部工作目录以同一配置运行 `<PYTHON_EXECUTABLE> -B -m douyin_wiki jobs events`；每轮从零扫描、包括跳过的事件在内按整页末尾推进，失败退避与重启重扫遵守 Gateway 指南。不在仓库里生成监控脚本、定时器配置或游标文件。

接入前后用只读文件清单、mtime 或内容 SHA 核对仓库，没有本次接入生成的文件或修改；清单本身放在外部目录，不运行仓库 Git 命令。发现未知变化时报告路径，不自动删除或还原他人的内容。

## 6. 记录结果和切换目标

按契约填写外部 `integration.json`：客户端与版本、实际配置位置、规则加载、开放工具、独立标识、验收结果、限制及回退方法。不创建仓库内 `clients/` 条目或追加客户端专属文档。

已有授权明确覆盖真实 Vault 和所选工具范围时，按以下顺序切换；否则保持隔离配置并报告尚缺的目标或权限。保留隔离验收结果，目标切换的检查重新标为待验收，尚未复核时不记录正式接入成功。

1. 读取并验证已存在的目标 TOML，核对真实 Vault 与已授权 Profile 均在仓库外。Profile 由 `DOUYIN_WIKI_BROWSER_PROFILE` 单独指定，不能只改 `DOUYIN_WIKI_CONFIG` 而保留测试 Profile。
2. 暂停本实例的监控和新任务派发，等待在途调用结束，关闭本实例的 MCP 连接并确认旧 STDIO 进程已退出。现有服务在首次业务调用后缓存配置；修改文件、客户端设置或对旧进程再次 `initialize` 都不会清除该缓存。不要停止其他实例或系统现有 Worker。
3. 按步骤 4 备份并合并客户端设置，以目标配置、Profile、仓库外 cwd 和禁用字节码的环境启动新的 MCP 进程，重新执行 `initialize`、`tools/list` 并核对开放工具和规则加载。不能确认旧进程退出或不能启动新进程时，记录阻塞，不继续派发任务。
4. 从客户端实际启动记录或进程信息确认新进程使用目标环境，核对该环境解析所得的 Vault、Profile 和状态库路径；权限允许时再读取获授权的已知条目或 job 验证归属。单独启动的 CLI / Python 探针，或一次空查询，都不足以证明当前 MCP 进程已切换。按所选角色复核受配置变化影响的能力，不能沿用测试目标的通过结果。
5. 使用监控时，将其配置环境同步到同一目标并复核后再恢复运行；采集 / 分析角色同时核对目标 Worker 的 Vault / Profile。更新 `integration.json` 中的最终配置、Vault、Profile、连接重建、目标绑定及适用的监控验收结果。失败时保持派发暂停，报告限制或按步骤 7 回退。

客户端配置回退不撤销已发生的知识库数据操作。

## 7. 重入、升级和回退

重复接入时从外部验收记录恢复参数，复用配置和实例标识，不新建重复条目或每次更换工作目录。客户端版本、文档来源 SHA 或启动环境变化时重新检查受影响的配置和能力；配置、Vault、Profile 或启动环境发生变化时，按步骤 6 重建连接并复核目标。后台状态按既有事件语义恢复，不跨轮保存会跳过失败事件的高水位。

回退时暂停本实例监控和派发，等待在途调用结束，关闭连接并确认旧 STDIO 进程退出；核对修改后的配置仍匹配本次记录，再恢复其外部备份或移除本次新增条目，保留其他客户端配置。恢复已有连接时，以原配置及 Profile 启动新进程，按步骤 6 复核目标和监控后恢复派发，不能只还原文件。只清理确认由本次创建且已无用途的外部临时文件，保留必要验收和恢复材料。项目代码、Git、服务环境及他人工作区不作为接入回退目标。
